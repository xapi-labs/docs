## Endpoints

The main xAPI entry point is `https://ai.xapi.to`. It supports **both** the Anthropic Messages and
OpenAI Chat Completions protocols:

| Endpoint | Protocol |
| --- | --- |
| `POST https://ai.xapi.to/v1/messages` | Anthropic Messages |
| `POST https://ai.xapi.to/{strategy}/v1/messages` | Anthropic, with an explicit strategy |
| `POST https://ai.xapi.to/v1/chat/completions` | OpenAI Chat Completions |
| `POST https://ai.xapi.to/{strategy}/v1/chat/completions` | OpenAI, with an explicit strategy |
| `POST https://ai.xapi.to/v1/messages/count_tokens` | Not implemented yet, returns 404 |
| `GET https://ai.xapi.to/openapi.json` | Live OpenAPI 3.0 spec (no authentication) |

`{strategy}` is one of `default | quality | speed | cost`.

<Tip>
  To lock a request to a specific upstream (skipping automatic routing), you can use the direct subdomain
  `https://{host}.p.xapi.to/{path}` as an advanced option.
  Aggregated routing already covers almost every case, so **prefer `ai.xapi.to`**.
</Tip>

## Authentication

Every endpoint accepts **either** of two authentication headers:

```http
x-api-key: sk-xapi-...
Authorization: Bearer sk-xapi-...
```

| Client | Default header | Extra setup needed |
| --- | --- | --- |
| Anthropic SDK / Claude Code | `x-api-key` | No |
| OpenAI SDK / Codex / Cursor | `Authorization: Bearer` | No |
| Hand-written curl / fetch | Either | — |

## Anthropic Messages request

<ParamField path="model" type="string" required>
  Model ID, for example `claude-opus-4-7`. See [Models and pricing](/en/ai/models) for the full list.
</ParamField>

<ParamField path="max_tokens" type="integer" required>
  Maximum number of tokens to generate.
</ParamField>

<ParamField path="messages" type="array" required>
  Array of conversation messages. Each item has a `role` (`user` | `assistant`) and `content`.
</ParamField>

<ParamField path="system" type="string">
  Optional system prompt.
</ParamField>

<ParamField path="stream" type="boolean" default="false">
  Whether to stream the response. Streaming responses are sent over SSE, with the same event structure as the official Anthropic API.
</ParamField>

<ParamField path="temperature" type="number" default="1.0">
  Sampling temperature, from 0 to 1.
</ParamField>

<ParamField path="tools" type="array">
  Tool / function definitions, passed through to the upstream.
</ParamField>

<ParamField path="tool_choice" type="object">
  Tool choice strategy, passed through to the upstream.
</ParamField>

Except for the `stream` and `priority` fields, the whole request body is passed through to the upstream.
All protocol headers that start with `anthropic-` (`anthropic-version`, `anthropic-beta` and so on)
are also passed through unchanged.

## Routing strategy

Aggregated routing takes the strategy from a URL path prefix. **The request and response bodies are not affected**:

| Path | Strategy |
| --- | --- |
| `ai.xapi.to/v1/...` | Default (same as quality) |
| `ai.xapi.to/quality/v1/...` | Explicit quality |
| `ai.xapi.to/speed/v1/...` | speed |
| `ai.xapi.to/cost/v1/...` | cost |

## Response headers

<ResponseField name="X-XAPI-Request-Id" type="string">
  A UUID generated by the platform, returned on every response. Include it in support tickets when troubleshooting.
</ResponseField>

<ResponseField name="X-XAPI-Source" type="string">
  `provider` (upstream response) or `platform` (gateway error).
</ResponseField>

<ResponseField name="X-AI-Cost" type="string">
  Amount charged for this request (USD, 8 decimal places). **Only returned for non-streaming requests with an upstream 2xx.**
</ResponseField>

<ResponseField name="X-AI-Tokens-Input" type="integer">
  Number of input tokens. Non-streaming with an upstream 2xx only.
</ResponseField>

<ResponseField name="X-AI-Tokens-Output" type="integer">
  Number of output tokens. Non-streaming with an upstream 2xx only.
</ResponseField>

<ResponseField name="X-AI-Tokens-Total" type="integer">
  Total number of tokens. Non-streaming with an upstream 2xx only.
</ResponseField>

<ResponseField name="X-Routing-Provider" type="string">
  ID of the upstream that aggregated routing actually used (for example `skyapi`).
</ResponseField>

<ResponseField name="X-Routing-Attempts" type="integer">
  Number of attempts. `> 1` means an automatic failover happened.
</ResponseField>

<ResponseField name="X-Routing-Fallback" type="boolean">
  Whether a fallback upstream was used.
</ResponseField>

<Warning>
  **Streaming responses do not return `X-AI-Cost` in the response headers**,
  because the headers have already been sent to the client when the stream starts.
  To get the actual cost of a streaming call, check Console → Usage Records.
</Warning>

## Error codes

### Platform errors (`X-XAPI-Source: platform`)

| HTTP | type | Meaning |
| --: | --- | --- |
| 400 | `invalid_request_error` | Field validation failed / model not configured in `tokenPricing` |
| 401 | `authentication_error` | API key invalid or missing |
| 402 | Payment Required | Insufficient account balance / API key limit exceeded |
| 429 | `rate_limit_error` | Upstream rate limit |
| 502 | `server_error` · `ALL_PROVIDERS_FAILED` | Every upstream in the candidate pool failed |
| 504 | `server_error` | Upstream request timed out |

### Upstream errors (`X-XAPI-Source: provider`)

The HTTP status code and response body come from the upstream. xAPI passes them through as is, without rewriting anything.

## Auto-generated OpenAPI

Every upstream provides a live-generated OpenAPI 3.0 spec:

```bash
curl https://ai.xapi.to/openapi.json
```

Each endpoint in the spec includes an `x-billing` extension field:

```json
{
  "x-billing": {
    "type": "PER_TOKEN",
    "pricingMode": "PER_MODEL",
    "allowedModels": ["gpt-5.5", "claude-opus-4-7"],
    "strictModelValidation": true,
    "modelPricing": {
      "claude-opus-4-7": {
        "inputPricePerToken": 0.0000010,
        "outputPricePerToken": 0.0000050,
        "cacheCreationPricePerToken": 0.00000125,
        "cacheReadPricePerToken": 0.0000005
      }
    },
    "streaming": { "supported": true, "format": "sse" },
    "estimatedMaxTokens": 4096
  }
}
```

You can import it straight into Swagger UI, Stoplight, Postman and similar tools to browse and debug it.

## Platform limits

- **Request body size**: ≤ 20 MB (Traefik body-limit middleware)
- **Connection timeout**: 2 minutes (`UPSTREAM_TIMEOUT_MS`; the streaming phase is not subject to this limit)
- **Redirects**: not followed (`maxRedirects: 0`; 3xx status codes are passed straight through to the caller)
- **SSRF protection**: DNS resolution and IP pinning happen before forwarding, as defense in depth against DNS rebinding
