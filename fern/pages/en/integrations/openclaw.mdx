[OpenClaw](https://github.com/openclaw/openclaw) is an open-source, cross-platform local AI assistant CLI.
It registers any OpenAI-compatible provider through JSON configuration. xAPI accepts `Authorization: Bearer` as is,
which is fully compatible with OpenClaw's `openai-completions` provider.

<Steps>
  <Step title="Install">
    Follow OpenClaw's official installation guide:
    [github.com/openclaw/openclaw](https://github.com/openclaw/openclaw).
  </Step>

  <Step title="Create an API Key">
    Go to the [xapi.to](https://xapi.to) console → **API Keys** → create a new key.
    The key looks like `sk-xapi-...`.
  </Step>

  <Step title="Configure ~/.openclaw/openclaw.json">
    Register xAPI as a custom provider under `models.providers`:

    ```json
    {
      "models": {
        "mode": "merge",
        "providers": {
          "xapi": {
            "baseUrl": "https://ai.xapi.to/v1",
            "apiKey": "${XAPI_KEY}",
            "api": "openai-completions",
            "timeoutSeconds": 300,
            "models": [
              {
                "id": "claude-opus-4-7",
                "name": "Claude Opus 4.7 (xAPI)",
                "contextWindow": 200000,
                "maxTokens": 8192
              },
              {
                "id": "claude-sonnet-4-6",
                "name": "Claude Sonnet 4.6 (xAPI)",
                "contextWindow": 200000,
                "maxTokens": 8192
              },
              {
                "id": "gpt-5.5",
                "name": "GPT-5.5 (xAPI)",
                "contextWindow": 128000,
                "maxTokens": 8192
              }
            ]
          }
        }
      },
      "agents": {
        "defaults": {
          "model": {
            "primary": "xapi/claude-opus-4-7"
          }
        }
      }
    }
    ```

    Export the `XAPI_KEY` environment variable in your shell:

    ```bash
    export XAPI_KEY="sk-xapi-..."
    ```

    <Note>
      `baseUrl` must **end with `/v1`** (OpenClaw requires this for OpenAI-compatible endpoints).
      `api: "openai-completions"` uses the OpenAI Chat Completions protocol,
      which matches xAPI's subdomain endpoints. Model ids use the native names of the xAPI upstream as is
      (see [Models and pricing](/en/ai/models)).
    </Note>
  </Step>
</Steps>

## Pin to a specific upstream (optional)

Just change `baseUrl`:

| Upstream | baseUrl |
| --- | --- |
| SkyAPI (widest model selection) | `https://skyapi.p.xapi.to/v1` |
| SuperToken Max (official source) | `https://supertoken-max.p.xapi.to/v1` |
| SuperToken reverse-engineered (lowest cost) | `https://supertoken.p.xapi.to/v1` |

## Switching models

Change the `agents.defaults.model.primary` field, or add new entries to the `models[]` array.
Model ids use the format `provider-id/model-name`, for example `xapi/claude-sonnet-4-6`.

## FAQ

<AccordionGroup>
  <Accordion title="404 Not Found">
    `baseUrl` is missing the `/v1` suffix. The full format is `https://ai.xapi.to/v1`.
  </Accordion>

  <Accordion title="401 Unauthorized">
    - The `XAPI_KEY` environment variable isn't exported, or OpenClaw didn't pick it up. Run `echo $XAPI_KEY` to confirm
    - You can also put the key in plain text in the `apiKey` field (not recommended for production)
  </Accordion>

  <Accordion title="Models don't show up in the interface">
    OpenClaw persists provider configuration to the agent-scoped
    `~/.openclaw/agents/<agent>/agent/models.json`.
    After you edit `openclaw.json`, you may need to select the agent again or restart OpenClaw for the merge to take effect.
  </Accordion>
</AccordionGroup>
