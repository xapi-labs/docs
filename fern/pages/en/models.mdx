## Automatic routing to the lowest price

When you call `https://ai.xapi.to/cost/v1/messages`, the gateway automatically picks the cheapest healthy upstream at that moment.
To lock in a specific upstream, use the direct subdomain `{host}.p.xapi.to/v1` (see the [API reference](/en/ai/api)).

## Model name matching

The gateway resolves the `model` field of a request in this order:

<Steps>
  <Step title="Exact match">
    Looks for an identical key in the endpoint's `tokenPricing` configuration.
  </Step>
  <Step title="Case-insensitive match">
    `Claude-Opus-4-7` and `claude-opus-4-7` are equivalent.
  </Step>
  <Step title="Strip the provider prefix">
    `anthropic/claude-opus-4-7` has `anthropic/` stripped first, then matching is tried again.
  </Step>
  <Step title="default fallback">
    If none of the above match and the endpoint has `default` pricing configured, `default` is used.
  </Step>
  <Step title="Reject">
    If the endpoint has no `default` configured, the gateway returns **HTTP 400** with `allowedModels` listed in the response body.
  </Step>
</Steps>

## Billing types

The `billingType` field of an xAPI endpoint takes one of three values; AI endpoints always use `PER_TOKEN`:

- **PER_TOKEN**: billed as input / output token count × the model's unit price (AI endpoints)
- **PER_CALL**: billed per call (regular REST APIs)
- **PER_RESOURCE**: billed by resource usage (for example, image generation per image)

A single proxy service handles every billing type through host-based gateway routing.
This is fully transparent to callers: you don't need to care how the backend bills.

## Separate billing for cache tokens

Claude models support prompt caching, and xAPI bills cache writes and cache reads separately:

- `cacheCreationPricePerToken` — cache writes, usually the input price × 1.25
- `cacheReadPricePerToken` — cache hit reads, usually the input price × 0.10

<Note>
  OpenAI's `cached_tokens` field is nested inside `prompt_tokens`.
  xAPI normalizes it automatically when it records usage:
  `inputTokens = prompt_tokens − cache_creation_tokens − cache_read_tokens`,
  so `inputTokens` always means regular, non-cached input tokens.
</Note>

## Choosing a model

| Scenario | Recommended |
| --- | --- |
| Code refactoring / complex reasoning | `claude-opus-4-7` |
| High-volume chat / customer support | `claude-haiku-4-5` or `gpt-5.5` |
| Moderate reasoning / balancing performance and cost | `claude-sonnet-4-6` |
| Image generation | `gpt-image-2` |
| Not sure | Use the `quality` strategy of aggregated routing |
