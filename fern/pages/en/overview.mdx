xAPI provides two kinds of infrastructure for AI applications. **AI Gateway** handles model inference and routing across
upstreams; **Sandbox** handles isolated compute, code execution and instance lifecycle. You can use either one on its own,
or combine them into an agent workflow where "the model plans and Sandbox executes".

<CardGroup cols={2}>
  <Card title="AI Gateway" href="/en/ai/overview" icon="brain">
    Call Claude, GPT, Gemini, DeepSeek, Kimi and other models through one gateway. Compatible with the Anthropic and
    OpenAI protocols, with routing across upstreams, streaming responses, failover and token billing.
  </Card>
  <Card title="Sandbox" href="/en/sandbox/overview" icon="terminal">
    Create isolated, temporary cloud environments to run commands, read and write files, expose ports and run GPU jobs,
    with a history of instances, operations, usage and settlements.
  </Card>
</CardGroup>

## How the two products differ

| | AI Gateway | Sandbox |
| --- | --- | --- |
| Core purpose | Call and route large models | Run code and workloads |
| Main endpoint | `https://ai.xapi.to` | `https://sandbox.xapi.to` |
| Resource unit | Model requests, tokens | Instances, CPU, memory, GPU, run time |
| Lifecycle | A single HTTP / SSE / WebSocket session | Quote, create, execute, suspend, resume, terminate |
| Main logs | Model, tokens, latency, cost, routing | Operations, events, usage segments, billing periods, instance status |
| Typical clients | OpenAI/Anthropic SDKs, IDEs, AI apps | xAPI CLI, Agent Tool, OpenAI Agents Sandbox |

<Note>
  Sharing an API key does not mean sharing an API. Use AI Gateway to call models; use Sandbox when you need a shell,
  a file system, web previews or GPUs.
</Note>
